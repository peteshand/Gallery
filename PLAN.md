# Gallery delivery plan

The app uses Haxe/Eva for the UI, Tauri 2 for the desktop and mobile shell, Rust for file and cloud operations, and a separate SQLite catalogue on each device. S3 will hold shared media and catalogue changes. The first import source is `I:\Photos\Best of Poe 2`; source files remain read only.

## 1. Prove the local flow on Windows — initial prototype

Import the 111 photos in the test folder, pair Takeout sidecars, deduplicate by SHA-256, keep a local SQLite catalogue and preview cache, and browse by date, collection, search, and full-screen viewer. Preserve Takeout dates, descriptions, locations, and favourites; allow the user to change a favourite. The browser flow passed a headless end-to-end run. The latest Windows executable was launched and visually verified with cached photos, the viewer and metadata panel, folder selection, a duplicate-safe repeat import, and a favourite change. Its local catalogue has 111 assets, 74 favourites, 111 geotagged assets, and 111 Takeout dates.

## 2. Add secure S3 connection settings

Add **Settings → Cloud storage** for bucket, region, optional endpoint/prefix, access key ID, and secret. Pass new credentials once to Rust and save them in the platform's protected credential store. Keep the secret out of Haxe storage, SQLite, source code, logs, and sync objects. Show only connection state and a masked key ID after saving. Validate the connection with a read-only request and support replacement/removal. The Windows native form, Credential Manager storage, masked saved fields, replacement/removal, and read-only SDK request are implemented; the user confirmed the live bucket check passed. macOS Keychain and Android Keystore adapters compile, but persistence testing on those devices remains. [`docs/CREDENTIALS.md`](docs/CREDENTIALS.md) has the detailed flow and checks.

## 3. Upload media and synchronize catalogues

The first Windows upload slice is implemented: **Sync now** uploads pending imported photos, while a photo's Details panel and a contextual multi-selection bar can back up exactly the chosen photos. Desktop selection supports long press, Ctrl/Command-click to add photos, Shift-click for a contiguous range, and an ordinary click to clear selection and open a photo. Touch selection supports long press, taps, and dragging across a range with edge scrolling. Settings can cancel a running backup after the current S3 object request. Uploads include untouched originals, orientation-corrected 1920-pixel JPEG previews, 320-pixel JPEG thumbnails, and versioned JSON manifests under stable content-addressed S3 keys. The manifest is written last. Local SQLite tracks object-level progress and per-photo states; a later run skips completed objects. Settings shows a batch count and current photo, and tiles show synced, active, failed, or not-synced badges. Locally cached derivatives are used for the grid and viewer once generated. Changing a favourite queues its manifest for re-upload. The design and current limits are in [`docs/SYNC_DESIGN.md`](docs/SYNC_DESIGN.md).

The fresh-device flow is implemented in the Windows prototype: remote manifests populate an empty SQLite catalogue, viewport tiles request thumbnails, the viewer requests a preview, and an explicit export downloads the verified original. A configurable cache (2 GB default) evicts least recently used media. Favourite changes use immutable per-device events under `catalog/events/<device>/...` with a deterministic Lamport-clock conflict rule. A live read-only S3 test imported all 111 remote manifests into a fresh catalogue and fetched a thumbnail. A separate live S3 test passed favourite changes between two isolated simulated devices, including concurrent offline edits. Repeat cloud refreshes skip unchanged manifest downloads using S3 ETags. Cross-device convergence is not yet verified on Android. Compressed snapshots, incremental cursors, album IDs, deletion tombstones, and general metadata edit events remain. Acceptance: a photo imported on Windows appears on a fresh device after sync, then a favourite changed on either device converges after both sync again, including after an offline period.

## 4. Make import safe for the full 90 GB library

A [read-only archive preflight](docs/ARCHIVE_AUDIT.md) counted 87,475 files and 91.10 GiB across 102 folders. The supported still-image formats account for 41,664 files and 63.74 GiB; 2,650 `.MP` motion companions and 811 MP4 videos are outside the current importer. The whole-archive import has not been run.

All folder imports now use the recursive Takeout importer, which handles JPEG, PNG, GIF, and WebP and uses per-file SQLite checkpoints, SHA-256 deduplication, bounded-size JPEG previews and thumbnails, progress, and cancellation. It leaves source originals in place. A real `I:\Photos\2003` test imported 18 photos with Takeout dates and resumed without duplicates; a separate cancellation test resumed without duplicate rows. The gallery now adds tiles in 160-photo batches as the user scrolls. Per-file errors now persist in SQLite across restarts, appear in Settings, and clear after a successful retry. HEIC, motion-photo companions, fully bounded DOM virtualization, and low-disk stress testing remain. A real flat-folder import of all 111 `I:\Photos\Best of Poe 2` photos and a duplicate-safe repeat pass completed with the new path without changing source files. A real `I:\Photos\Photos from 2007` test imported 354 photos with Takeout dates and a duplicate-safe second pass in 173 seconds with the 0.7.1 optimized build (481 seconds before the small-JPEG preview optimization). Small unrotated JPEGs can be reused as previews, and failed cache writes clean up temporary files. Acceptance: restart or cancel mid-import without duplicate catalogue rows, lost favourites, corrupt previews, or source-file changes.

## 5. Bring up Android with the shared Haxe UI

Version 0.7.10 adds neutral placeholders without broken-image text, a stable viewer image frame as the preview arrives, three pinch-selectable grid densities (five squares, four squares, and a larger aspect-preserving layout), and drag-following viewer transitions. The signed APK and headless checks pass; physical phone verification is pending. The featured memory card remains at the top of the photo timeline. Image-derived placeholder colours are a later optional catalogue enhancement.

Next Android source: read the phone camera roll through MediaStore with the relevant photo permission, merge phone-local photos into the catalogue by content hash, and reuse the original/preview/thumbnail backup pipeline. Add **Auto back up photos**, default **off**, plus **Wi-Fi only** and background backup controls. The auto-backup switch must remain unavailable until a durable queue and Android background worker are implemented. New media detection should enqueue rather than immediately upload; the queue should survive process death, show per-photo and aggregate states, respect metered-network settings, and allow manual backup regardless of the auto setting. Avoid requesting all-files access. Phone-local files must remain untouched. Test permission denial/revocation, offline capture, Wi-Fi changes, charging/process restarts, duplicate captures, and app upgrades before enabling background upload.

The workspace-local JDK, Android SDK/NDK, and Rust ARM64 target are installed; the Tauri Android project and Android Keystore adapter compile. A signed 0.7.10 ARM64 debug APK exists at about 85 MB. Its `resources.arsc` and native library are stored uncompressed and aligned, and its signature verifies. The 0.7.1 compact APK failed installation because its native library was compressed despite `extractNativeLibs=false`; 0.7.2 compact still failed after Play Protect because `resources.arsc` was compressed by a ZIP repack. Version 0.7.3 preserves the Gradle APK intact. Version 0.6.3 explicitly initializes the keyring context before Tauri starts the WebView. A headless Android UI test confirms the fresh-device empty state leads to cloud Settings and hides desktop folder import. Version 0.7.4 installed on the CMF Phone 2 Pro and saved connection settings, but its S3 check remained pending. Version 0.7.5 exposed that the AWS SDK could not parse Android native TLS roots. Version 0.7.6 bundled verified Mozilla CA roots with TLS checks enabled; the user confirmed S3 access and cloud photo loading on the phone. Version 0.7.7 added viewer safe-area spacing and swipe-to-close. Version 0.7.8 extends safe-area spacing to the gallery header, Settings, navigation, and selection controls, awaiting phone UI verification. Credential persistence after restart, offline cache, and favourite convergence remain unverified. The user can transfer the APK and install it manually. Add phone-local import afterward through Android's Storage Access Framework and content URIs; the current desktop `PathBuf` importer and Tauri folder dialog do not provide that flow. Acceptance: a fresh phone configures its own S3 connection, syncs the test collection, opens photos offline, and sends a favourite change back to Windows.

## 7. Release gates

Test malformed sidecars, duplicate names/content, interrupted imports and uploads, low disk space, large libraries, expired or rotated credentials, S3 errors, conflict replay, and recovery from a new device. Inspect source, packaged assets, SQLite, and logs for credential leakage. Keep personal photos and test screenshots local.

A live read-only S3 test rebuilt a new catalogue from all 111 manifests, recognized them as unchanged on a second listing, and loaded a thumbnail, preview, and original. An isolated live S3 event test passed two simulated devices exchanging favourites, including concurrent offline edits. The 0.7.10 Android APK signature, package metadata, ABI, resources and native library were inspected; the Windows installer was built. A scan of source and packaged assets found no AWS access-key-shaped text. Device testing, installer upgrade testing, low-disk and large-library stress, credential rotation, production signing, and macOS validation remain open.
